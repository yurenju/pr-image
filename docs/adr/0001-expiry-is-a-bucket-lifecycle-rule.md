# 過期交給 bucket 的 lifecycle rule，不寫在程式裡

PR 圖片在 pull request 關掉之後就沒人看了，所以 30 天過期。這個過期是在 bucket 上設一次 R2 object lifecycle rule 做到的；工具本身完全沒有刪除邏輯，也不會去列出或移除任何 object。

## 考慮過的選項

- **lifecycle rule（採用）**：Cloudflare 在伺服器端刪。不需要有任何東西跑著，就算連續幾個月沒人上傳，過期一樣照常發生。
- **上傳時順手掃**：每次上傳順便列出舊 object 刪掉。好處是政策看得見、寫在 repo 裡；壞處是舊 object 只有在有人上傳的時候才會消失，工具一停用，東西就無限期躺著。
- **排程工作**：用 cron 或 Worker 定期清。做得到，但代價是要養一個永遠在跑的東西，而那正是這個設計一開始就想避開的。

## 後果

R2 API token 的權限只有單一 bucket 的 Object Read & Write，而**這個權限讀不到 bucket 的 lifecycle 設定**——要確認規則還在，得換一把權限更大的 token。所以工具沒辦法檢查這條規則，沒辦法警告，也沒辦法把它補回去。有人在後台把規則刪掉的話，儲存量會安靜地長，直到超過免費額度、帳單寄來為止。這是刻意接受的：另一個選項是讓憑證永久變大。

過期本身也是個大概。lifecycle rule 以整天計算，object 通常在到達歲數之後的一天之內消失，不會有準確的時間點。不要在上面蓋任何需要「某個 object 在某個時刻已經不存在」的東西。
