# Object key 是隨機的，不帶任何意義

Object 的 key 是一段猜不到的隨機值，後面接上 source file 的副檔名——沒有 repository 名稱、沒有日期、沒有 PR 編號、沒有原始檔名。bucket 是透過 custom domain 公開提供的，所以 key 裡編進去的東西，任何拿到網址的人都讀得到。

## 後果

`owner/repo/2026-08-02/…` 這種 prefix 結構其實很有吸引力：bucket 變得可以瀏覽，而且 R2 的 lifecycle rule 可以按 prefix 分類，於是「不同專案給不同過期時間」也變得可行。這兩件都是實實在在的損失。拿它們換掉的是：不對外公布有哪些 repository 存在、什麼時候在動它們、以及開發者把截圖取了什麼名字。

因此瀏覽 bucket 是沒有意義的，裡面的東西看不出名堂。這是預期的狀態，不是待補的缺口。

存取控制靠的就是「猜不到」：key 是唯一的秘密。它取自密碼學等級的隨機來源，長到猜不出來，但任何拿到網址的人，在它過期之前都看得到那張圖。真正敏感的截圖不該放這裡。
